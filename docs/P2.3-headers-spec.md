# P2.3 — Agent-Discovery HTTP Headers

**Spec owner:** Reed (CPO)
**Implementer:** Rex (CTO)
**Reviewer:** Cart (Agent Success Lead)
**Horizon:** 2026-12-31
**Status:** LOCKED — 2026-08-19

This document is the canonical contract for the five `X-Agent-*` response headers emitted by every BuyWhere endpoint. Implementation PRs (PR-1 `buywhere.ai`, PR-2 `api.buywhere.ai`, PR-3 docs) cross-link here and MUST NOT diverge from the values below.

## Why this exists

P2.3 measures **discoverability** — can an AI agent find BuyWhere's API in one round-trip from a single `curl`? The custom `X-Agent-*` namespace gives agents a deterministic trip:

1. Parse `X-Agent-Protocol` to confirm the contract version.
2. Fetch `X-Agent-Card` to retrieve the signed Agent Card.
3. Fetch `X-LLMs-Txt` for the human/agent-readable site manifest.
4. For catalog calls, parse `X-Agent-Index` for the templated search URL.
5. On 401/403, follow `X-Agent-Auth` to register an API key.

This sits between P2.2 (DONE) and P2.4 (DONE) on the agent-discovery roadmap.

## Header contract

| Header | When emitted | Value |
|---|---|---|
| `X-Agent-Protocol` | every response | `buywhere/v1` |
| `X-Agent-Card` | every response | `https://api.buywhere.ai/.well-known/agent.json` |
| `X-LLMs-Txt` | every response | `https://api.buywhere.ai/llms.txt` |
| `X-Agent-Index` | 200 catalog responses only | `https://api.buywhere.ai/v1/products?q={q}&country_code={cc}` |
| `X-Agent-Auth` | 401 and 403 responses only | `Bearer; register=https://buywhere.ai/api-keys` |

CORS: `Access-Control-Expose-Headers` lists all five header names. No wildcards. No extras.

## Hard rules (every PR)

- **Lowercase keys.** `x-agent-protocol`, not `X-Agent-Protocol`. HTTP/2 lowercases header names on the wire; document them lowercase.
- **Static values.** `X-Agent-Protocol`, `X-Agent-Card`, `X-LLMs-Txt`, and `X-Agent-Auth` are constant strings. Only `X-Agent-Index` is templated (the `{q}` and `{cc}` placeholders are part of the contract value).
- **No version churn.** `X-Agent-Protocol: buywhere/v1` is the only versioned token. Do not invent `v2` until this spec is retired.
- **Do not modify response bodies.** The middleware MUST NOT touch the existing Agent Card signature on `/.well-known/agent.json` or the `text/plain` body of `/llms.txt`. Gate 3 + 4 are already TRUE; the middleware just adds the header values that point at them.
- **No 5xx emission.** Headers are additive. On server errors (5xx), still emit `X-Agent-Protocol` + `X-Agent-Card` + `X-LLMs-Txt` so the agent can re-discover endpoints during partial outages.

## Per-header semantics

### `X-Agent-Protocol: buywhere/v1`

The contract version. Always present. Agents should refuse to parse `X-Agent-*` headers if this is missing or unrecognized (forward-compatibility sentinel).

### `X-Agent-Card`

URL to the signed Agent Card (P2.4). Fetching it returns a JWS that proves the BuyWhere origin — agents can pin the public key. Verified 2026-08-17 with EdDSA/Ed25519 (kid `buywhere-agent-card-20260816`); live re-verification is required if the signing key rotates — see `docs/P2.4-signed-agent-card-spec.md`. Already live at `https://api.buywhere.ai/.well-known/agent.json` (200 OK, `application/json`).

### `X-LLMs-Txt`

URL to the llms.txt manifest (P2.5). Fetching it returns `text/plain` describing the BuyWhere surface in a format LLM agents can ingest directly. Already live at `https://api.buywhere.ai/llms.txt`.

### `X-Agent-Index`

Templated URL for the canonical catalog search endpoint. ONLY on 200 responses to catalog endpoints (`/v1/products/search`, `/v1/products/compare`, `/v1/products/{id}`, `/v1/p/{id}` (PDP alias), `/v1/categories`, `/v1/deals`). Placeholders:

- `{q}` — the original query string (URL-encoded)
- `{cc}` — the resolved `country_code` (two-letter, e.g. `SG`, `US`)

Agents substitute the placeholders client-side; BuyWhere does not return a per-request URL.

### `X-Agent-Auth`

Authentication guidance for 401/403 responses. The value `Bearer; register=https://buywhere.ai/api-keys` tells agents (a) the auth scheme is `Bearer`, and (b) where to register a new key. Only emitted on `401 Unauthorized` and `403 Forbidden`. Never on `429` (rate-limit responses already carry `Retry-After` and `X-RateLimit-*`).

## Verification (paste-paste)

```bash
# Gate 1+2: every response carries X-Agent-Protocol
curl -sI https://buywhere.ai/ | grep -i '^x-agent-protocol'
curl -sI https://api.buywhere.ai/ | grep -i '^x-agent-protocol'

# Gate 3: Agent Card still valid
curl -sI https://api.buywhere.ai/.well-known/agent.json | head -3

# Gate 4: llms.txt still text/plain
curl -sI https://api.buywhere.ai/llms.txt | grep -i '^content-type'

# Gate 5: X-Agent-Index on 200 catalog
curl -sI 'https://api.buywhere.ai/v1/products/search?q=laptop&country_code=US' \
  -H 'Authorization: Bearer bw_test_xxx' | grep -i '^x-agent-index'

# Gate 6: CORS exposes all five
curl -sI 'https://api.buywhere.ai/v1/products/search?q=laptop&country_code=US' \
  -H 'Authorization: Bearer bw_test_xxx' \
  -H 'Origin: https://buywhere.ai' | grep -i '^access-control-expose-headers'

# Gate 5 inverse: X-Agent-Index NOT on 401
curl -sI 'https://api.buywhere.ai/v1/products/search?q=laptop' | grep -i '^x-agent'

# X-Agent-Auth on 401/403
curl -sI 'https://api.buywhere.ai/v1/products/search?q=laptop' | grep -i '^x-agent-auth'
```

## Out-of-scope (P2.3 explicitly does NOT do)

- `X-Agent-Index` body content (metadata, hit counts) — only the templated URL.
- Versioning beyond `buywhere/v1`.
- New directory listings (P2.1 already covers).
- Modifying the Agent Card signature or the `llms.txt` body — those are P2.4 / P2.5 deliverables, already DONE.
