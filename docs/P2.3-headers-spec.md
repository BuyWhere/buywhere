## 1. Problem Statement

Today, an AI agent crawling `https://buywhere.ai/` or `https://api.buywhere.ai/` discovers the catalog surface through DNS TXT + `llms.txt` + `/.well-known/agent.json` + `/.well-known/api-catalog`. **But that discovery is opportunistic**, not signaled. An agent that asks "is this site agent-native?" cannot answer from a single header — it has to fetch 4+ documents and parse them.

The current response headers `curl -I https://buywhere.ai/` returns NO signal of agent-readiness:

```
HTTP/2 200
cache-control: s-maxage=300, stale-while-revalidate
content-type: text/html; charset=utf-8
link: <https://buywhere.ai/llms.txt>; rel="describedby"; ...
server: railway-hikari
vary: RSC, Next-Router-State-Tree, ...
x-nextjs-cache: HIT
x-powered-by: Next.js
```

Agents need a single header trip — `X-Agent-Protocol: buywhere/v1` — to short-circuit the "is this site agent-native?" question. The current `link:` rel="describedby" for `llms.txt` is good but agents parsing the bare 200 response rarely walk the Link header.

## 2. Live evidence (Reed, 2026-08-19T10:28Z)

```
$ curl -sI https://buywhere.ai/ | grep -iE 'x-agent|x-llms'
(empty — no agent-discovery headers)

$ curl -sI https://api.buywhere.ai/v1/products/search?q=laptop&country=US \
    -H "Authorization: Bearer bw_..." | grep -iE 'x-agent|x-llms'
(empty — no agent-discovery headers)
```

The `link:` header on `https://buywhere.ai/` includes `rel="describedby"` for llms.txt (already shipped, P2.2), but **no HTTP-level agent marker** is present.

## 3. Acceptance Gate

### 3.1 Wire contract

Every response from `https://buywhere.ai/*` and `https://api.buywhere.ai/*` carries:

| Header | Value | When |
|---|---|---|
| `X-Agent-Protocol: buywhere/v1` | Always | 200/4xx/5xx responses |
| `X-Agent-Card: https://buywhere.ai/.well-known/agent.json` | Always | discovery target |
| `X-LLMs-Txt: https://buywhere.ai/llms.txt` | Always | LLM-readable context |
| `X-Agent-Index: https://api.buywhere.ai/v1/products/search?q={q}&country={cc}` | Only on 200 responses | primary catalog endpoint |
| `X-Agent-Auth: Bearer` (or `apikey`) | Only on 401/403 | auth signal |

The headers are **additive**, **lowercase**, and **never duplicate** within a single response (one value per header; multi-value via repeated header lines if needed). CORS-safe — exposed to all origins via `Access-Control-Expose-Headers`.

### 3.3 Why this is a P2 item (not P1)

P1.3 measures **relevance** (zero-result rate <1%). P2.3 measures **discoverability** — agents finding the API in the first place. They are complementary. P2.3 is shipping NOW because no spec existed and the wire contract is one PR.

## 4. Design Decisions

### 4.1 Why a custom `X-Agent-*` namespace and not RFC 9309 `Link` rel

`Link: <https://buywhere.ai/.well-known/agent.json>; rel="agent-card"` is spec'd but NOT universally parsed by agent frameworks. A custom `X-Agent-*` namespace is unambiguous, easy to grep, and shows up in any `curl -I` head dump — which is exactly the agent-discovery surface.

### 4.2 Why `buywhere/v1` (versioned token)

Agents should be able to gate on protocol version. Future `buywhere/v2` can ship with breaking changes without breaking v1 customers. The token is short and parseable.

### 4.3 Why `X-Agent-Index` only on 200 responses

A 404 with `X-Agent-Index` is misleading — the index is the alive search endpoint. A 401/403/404 should NOT advertise the index. The auth-only `X-Agent-Auth` header on 401/403 tells the agent WHICH auth scheme to use.

### 4.4 Why CORS `Access-Control-Expose-Headers`

Browser-side agent toolchains (e.g. LangChain in-browser) cannot read custom headers by default. `Access-Control-Expose-Headers: X-Agent-Protocol, X-Agent-Card, X-LLMs-Txt, X-Agent-Index, X-Agent-Auth` is required for browser clients.

## 5. Detection Heuristics (Rex implementation guide)

| Header | Body cost |
|---|---|
| `X-Agent-Protocol` | Static in `next.config.js` headers() + Express middleware |
| `X-Agent-Card` | Static URL |
| `X-LLMs-Txt` | Static URL |
| `X-Agent-Index` | Templated: `https://api.buywhere.ai/v1/products/search?q={searchParams.q}&country={searchParams.country_code}` |
| `X-Agent-Auth` | Static on 401/403 only |
