# P1.3 Near-Miss Rate Specification

> **Status:** Draft for BUY-71135 implementation  
> **Owner:** Cart (Agent Success Lead)  
> **Parent:** BUY-71131 [P1.3-NM] Near-miss rate <3% — Reed  
> **Date:** 2026-08-18

## 1. Overview

This document specifies the near-miss rate metric and its integration into the CEO KPI line, paired with the existing zero-result-rate metric.

### Goals

1. Make near-miss rate measurable in the daily CEO KPI line
2. Enable side-by-side display of both failure modes
3. Track rolling 7-day mean <3% AND individual sweep <4%

## 2. Definitions

### 2.1 Zero-Result Rate (existing P1.3)

```
zero_result_rate = queries_with_empty_results / qualifying_queries
```

- **Numerator:** Zero results in `products`/`results` array AND no error (2xx or MCP -32600-series with structured error)
- **Denominator:** `search_products` / `find_best_price` / `find_similar` MCP calls with valid country_code
- **Scope:** SG, US, MY, TH, VN

### 2.2 Near-Miss Rate (new P1.3-NM)

```
near_miss_rate = queries_with_useless_results / qualifying_queries
```

- **Numerator:** Results returned but none match query intent (per Rex's classifier: `near_miss: true`)
- **Denominator:** Same as zero-result rate
- **Predicate Fails:** List of reasons why results failed to match (e.g., `wrong_brand`, `wrong_category`, `low_relevance_score`)

## 3. Failure Mode Pair Display

Both metrics are displayed side-by-side in the CEO KPI line:

| Metric | Description | Target |
|--------|-------------|--------|
| `zero_result_rate` | No products returned | <1% |
| `near_miss_rate` | Products returned but not relevant | <3% (7-day mean), <4% (per-sweep) |

### Why Pair These?

- **Zero-result** = catalog gap (product not in DB)
- **Near-miss** = relevance gap (product in DB but wrong match)

Both require different fixes:
- Zero-result → Oracle fills catalog
- Near-miss → Rex improves ranking

## 4. Daily Sweep (23:55Z)

The 225-cell basket sweep runs nightly at 23:55 UTC:

- **Markets:** SG, US, MY, TH, VN (5)
- **Categories:** electronics, fashion, home, health, sports (5)
- **Query lengths:** short, medium, long (3)
- **Merchant domains:** amazon.com, shopee.sg, lazada.sg (3)
- **Total:** 5 × 5 × 3 × 3 = 225 cells

### Output Schema

Each row in `data/sweep/zrr/YYYY-MM-DD.jsonl`:

```json
{
  "market": "SG",
  "category": "electronics",
  "query_length": "medium",
  "merchant_domain": "amazon.com",
  "tool": "search_products",
  "query": "gaming laptop site:amazon.com",
  "result_count": 10,
  "latency_ms": 245,
  "error": null,
  "near_miss": false,
  "near_miss_predicate_fails": [],
  "swept_at": "2026-08-18T23:55:00.000Z"
}
```

## 5. KPI View (`v_ceo_kpis`)

The `monitoring.v_ceo_kpis` view provides daily aggregated metrics:

```sql
SELECT * FROM monitoring.v_ceo_kpis;
```

| Column | Type | Description |
|--------|------|-------------|
| `report_date` | DATE | Report date |
| `zero_result_rate` | NUMERIC | Zero-result rate from existing P1.3 |
| `near_miss_rate` | NUMERIC | Near-miss rate (7-day rolling mean) |
| `near_miss_7day_mean_under_threshold` | BOOLEAN | True if <3% |
| `near_miss_latest_sweep_under_threshold` | BOOLEAN | True if <4% |
| `p1_3_nm_status` | TEXT | healthy / warning / critical |
| `computed_at` | TIMESTAMP | Computation timestamp |
