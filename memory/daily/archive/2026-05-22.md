## Decisions and reasoning

- Did **not** try to "make get_deals return rows" by repointing the API at the larger DB. Two reasons: (1) memory rule above — that DB is the platform DB, not a catalog; (2) the 14M row count on the API-side DB is unverified-provenance and tied to the BUY-22153 fabrication incident. Repointing would have masked the real fix and re-coupled API to platform DB.
- Routed canonical-catalog-DB choice through the board (approval 65fed55d) rather than picking unilaterally. Two viable paths (designate DB-A vs provision fresh dedicated DB) and the fabrication-purge implications mean this needs Vera + board, not CTO fiat.
- Accepted that BUY-22316/22317/22334 sit blocked tonight rather than forcing through. Each has a named blocker and owner — that is the correct disposition, not a stall.
